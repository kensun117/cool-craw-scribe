# Phase 2: OpenClaw 会议交互功能

> 状态：待实现（Phase 1 完成后开始）

## 功能概述

会议进行中，与会者可以通过语音自然地触发 OpenClaw 处理任务。OpenClaw 根据会议处理流程（Skill 定义）判断并执行，结果返回到 Discord 文字频道供与会者确认。

## 交互流程

```
1. 与会者说话，例如：
   "OpenClaw 去查一下用哪种方法实现这个功能最方便？"
        ↓
2. 转录程序实时转录文字，监控程序检测到触发词 "OpenClaw"
        ↓
3. 提取触发词后面的请求内容 + 最近 N 条上下文（会议讨论背景）
        ↓
4. 发送给 OpenClaw Gateway
        ↓
5. OpenClaw 按照会议处理流程（Skill 定义）判断：
   - 是否需要自己处理
   - 转换为具体问题
        ↓
6. OpenClaw 将问题发到语音频道的文字聊天中，等待与会者确认：
   🤖 OpenClaw: "你是想了解：实现 XX 功能时，A 方案和 B 方案哪个更方便和安全？"
   [确认执行] [修改问题] [忽略]
        ↓
7. 与会者点击按钮确认
   - 确认执行 → OpenClaw 开始处理
   - 修改问题 → 弹出编辑框修改后再执行
   - 忽略 → 不处理
        ↓
8. OpenClaw 处理完毕，结果发到频道：
   🤖 OpenClaw 回复：
   方案 A（Vercel）：部署简单，适合前端项目...
   方案 B（Docker）：更灵活，适合全栈...
        ↓
9. 该回复可选择是否采纳进入会议纪要
```

## 显示位置

所有交互（确认问题、处理结果）都发送到**语音频道的文字聊天**中，与实时转录在同一个地方，与会者不需要切换频道。

## 辅助触发方式

- 对任意历史转录消息添加 🤖 Reaction，触发 OpenClaw 处理该条内容
- 直接在文字频道 @OpenClaw + 文字描述

## 技术要点

### 触发词检测
- 在转录文本中匹配关键词："OpenClaw"（及可配置的别名列表）
- 文本级匹配，不需要声学级唤醒词模型

### 上下文窗口
- 触发时携带最近 N 条转录记录作为会议背景
- N 可配置（默认 10 条或最近 2 分钟）

### Discord UI 交互
- 使用 Discord Button（`discord.ui.View`）实现确认/修改/忽略按钮
- 使用 Discord Modal 实现修改问题的编辑框

### OpenClaw Gateway 协议
- WebSocket 连接，消息类型 `voice_command`
- 请求体包含：触发文本、上下文、说话人、频道 ID
- 响应体包含：确认问题、处理结果
